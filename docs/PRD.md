# agent-matrix 需求事实源

更新日期：2026-10-24。本文只定义需求与验收，不定义实现。REQ ID 永久保留，不随排序改变。

## 事实等级与来源

- **CONFIRMED**：负责人明确指令、已确认需求或真实仓库证据直接支持。
- **INFERRED**：从现有描述合理推断，尚未获负责人确认，不构成开发授权。
- **TODO_CONFIRM**：范围、规则或边界缺失，须负责人决策，不能自行补齐。
- 来源 S1：负责人于 2026-10-24 提供的《项目多 Agent 工程化初始化指令》。
- 来源 S2：初始化时的中英文项目说明，仅作为历史愿景来源，不能证明功能已实现。
- 来源 S3：负责人于 2026-10-24 明确开源定位，并授权“根据建议完善工程，直至可以提交 git”；许可证明确选择 MIT，署名 agent-matrix contributors。

## 背景与目标

**CONFIRMED（S1）**：当前需要建立轻量、可持续的研发闭环，减少需求猜测、设计冲突和进度失真。本次目标是工程治理初始化，不能据此授权开发产品功能。

**CONFIRMED（S3）**：向开发者、技术负责人和开源维护者交付轻量、可复用的多 Agent 研发方法包，包含规范、工作流、文档契约模板与协作机制。首版支持人工协调的人/Agent 协作，不提供自动编排服务或云部署平台。决策依据见 [DEC-001](DESIGN.md#决策记录)。

| 角色 | 事实等级 | 需求 |
| --- | --- | --- |
| 项目负责人 | CONFIRMED / S1 | 决定范围、确认共享设计、选择任务、裁决争议 |

## 范围与功能需求

需求共 9 项：CONFIRMED 8、INFERRED 0、TODO_CONFIRM 1。REQ-006 是延后的候选愿景，不阻塞本版；以下验收是预期标准，完成证据见任务及审核记录。

### REQ-001 研发过程可追溯

- 事实等级：**CONFIRMED**；来源：S1。
- 需求：每个交付任务都能追溯到需求、设计、实现、验证和审核；进度有唯一记录，代码完成不能直接等同交付完成。
- 验收：任取一个任务可以定位关联需求、设计、依赖、范围、验收标准和状态；若已完成，还能定位真实验证与审核依据。

### REQ-002 交付质量可验证

- 事实等级：**CONFIRMED**；来源：S1。
- 需求：审核保留所有参与者的证据与意见；未解决的阻断或高风险问题必须阻止交付。
- 验收：审核包含问题严重度、证据、处置和复核结果；存在未解决 P0/P1 时结论为 FAIL，任务不能完成或合并；未运行验证必须如实记录。

### REQ-003 变更与协作受控

- 事实等级：**CONFIRMED**；来源：S1。
- 需求：先明确需求与设计再执行变更；保护其他参与者已有工作；待确认事项经确认后及时回写，避免过期结论继续传播。
- 验收：能追踪需求到任务的变更影响；同一任务或文件只有一个写入主体；初始化与执行授权分开，保护已有工作，不擅自迁移、部署或提交。

### REQ-004 可复用的协作标准

- 事实等级：**CONFIRMED**；来源：S3；Q-001 已解决，见 DEC-001。
- 需求：用户可采用同一套方法完成初始化、指定任务、目标推进、需求变更和设计变更；复用时能区分通用规则、项目事实和示例。
- 验收：提供可复制的初始化指令、最小契约模板及完整示例；不依赖维护者的本机文件；已有项目采用时不覆盖原文档或强制改变技术栈、目录。

### REQ-005 多 Agent 协作能力

- 事实等级：**CONFIRMED**；来源：S3；Q-002 在本版范围内解决，见 DEC-001。
- 需求：人和多个 Agent 按共同规则交接与审核，明确写入归属、争议处理与人工介入。首版采用人工协调，不承诺自动调度。
- 验收：规则覆盖认领冲突、共享文件写入、异常退出、交接和释放；审核意见保留历史；明确模型角色是建议，单人也可采用，不冒充独立审核。

### REQ-006 本地到云端交付能力

- 事实等级：**TODO_CONFIRM**；来源：S2 中“bridge local prototyping to cloud deployment”仅有愿景。
- 候选需求：工作成果可以从本地阶段进入云端交付阶段。
- 待定验收：负责人必须明确交付对象、目标环境、权限边界、成功条件和失败后的恢复预期；当前没有可执行的功能验收标准。
- 关联 Q-003；不能把愿景当作部署授权。
- 本版范围：延后候选，不是本次开源方法包的发布条件；后续如需产品化，先确认需求再设计。

### REQ-007 开源采用与贡献入口

- 事实等级：**CONFIRMED**；来源：S3。
- 需求：外部采用者能快速理解痛点、工作流、交付物、接入步骤与贡献方式。
- 验收：中英文入口信息一致；包含方法导航、接入指南、明确标注的示例、支持边界和贡献流程；没有占位安装说明或未经证实的生产就绪承诺。

### REQ-008 验证可复现

- 事实等级：**CONFIRMED**；来源：S3。
- 需求：采用者能在本地检查交付物的结构和一致性，维护者能核对实际提交内容。
- 验收：检查方法随仓库交付，验证追踪引用、任务统计/依赖、文档链接、提交卫生；包含正常与异常场景，能发现暂存旧版本或不应发布的本地文件；验证真实运行，不声称代替人工判断或生产认证。

### REQ-009 许可与发布卫生

- 事实等级：**CONFIRMED**；来源：S3；许可证决策见 DEC-002。
- 需求：交付物采用 MIT，署名 agent-matrix contributors；发布内容不夹带个人配置、机器路径或本地临时依赖。
- 验收：许可文本随仓库交付，提交范围明确；本地配置保留在用户机器但不进入提交；工作区最终版本与待提交版本一致，不自动提交或推送。

## 业务流程与规则

**CONFIRMED（REQ-001～REQ-003）**：负责人提出或确认需求 → 明确设计 → 拆解有依赖的任务 → 选择一个任务 → 实现与验证 → 审核与修复 → 满足全部验收后完成。

**CONFIRMED（S1）**：需求变化必须先更新需求，再分析设计和任务影响，最后开发。历史已完成任务保留，增量变更新建任务。未确认的候选需求不得默认为必做范围；争议须有证据，无法裁决时由负责人决定。

**CONFIRMED（S3）**：外部采用流程为理解方法 → 扫描目标项目 → 增量初始化 → 确认需求和设计 → 选择任务 → 验证与审核 → 完成与演进。本项目本身交付该方法，不要求采用者引入运行时平台。

## Out of Scope

**CONFIRMED（S3）**：首版不提供自动 Agent 调度器、托管服务或云部署平台；不预设采用者的业务与技术栈。本次授权包含文档、示例、必要的验证工具及提交准备，不包含实际 commit、push、生产部署、数据库变更或覆盖用户已有工作。历史初始化的只读/仅文档边界只约束当时阶段。
